WHAT THIS PROJECT IS
--------------------
A local Windows desktop app (Python + Flask) that:
1. Accepts a tender document (paste text OR upload PDF/Word/PPT/TXT)
2. Calls Google Gemini AI to generate a complete Arabic proposal (JSON)
3. Builds a professional PowerPoint file (PPTX) from that JSON
4. Saves the PPTX to: C:\Users\PC\Downloads\Proposals_2026\completed\
5. Saves a review checklist to: C:\Users\PC\Downloads\Proposals_2026\review_needed\
6. The user opens the chatbot at http://localhost:5050 in their browser

The company is "زواد للتطوير والاستشارات" (Zawad for Development and Consulting),
an Omani training/consulting firm that submits proposals for government tenders.

CHATBOT.PY — FLASK SERVER
================================================================

URL: http://localhost:5050
Routes:
  GET  /              → serves chat_ui/index.html
  GET  /api/status    → returns current session mode and proposal info
  POST /api/chat      → main chat endpoint (JSON body: {"message": "..."})
  POST /api/upload    → file upload endpoint (multipart/form-data, field: "file")

Session state (in-memory, single user, resets on server restart):
  session['mode']          — 'await_key' | 'await_draft' | 'ready'
  session['api_key']       — Gemini API key string
  session['proposal_data'] — dict of the current proposal JSON
  session['draft_text']    — original tender text that was submitted
  session['pptx_path']     — path to the saved PPTX file

Flow:
  1. If no API key in config.json → mode = 'await_key'
     User pastes Gemini API key → saved to config/config.json → mode = 'await_draft'
  2. mode = 'await_draft': user pastes tender text OR uploads file
     → _generate_new(text) is called
  3. mode = 'ready': user types corrections/edits
     → _patch_existing(correction) is called
     → typing "عرض جديد" or similar resets to 'await_draft'

File upload flow (/api/upload):
  - Accepts: .pdf, .docx, .doc, .pptx, .ppt, .txt
  - Saves to temp file → reader.py extracts text → calls _generate_new(text)
  - Minimum text length check: 30 characters (internal to upload handler)
  - NOTE: The /api/chat endpoint no longer has a 40-char minimum. It only
    blocks completely empty messages.

_generate_new(draft_text) — 4 steps:
  1. extractor.extract_requirements(text, api_key) → structured checklist
  2. generator.generate_proposal(text, api_key, checklist) → proposal dict
  3. builder.build_pptx(proposal_data, output_path) → saves PPTX
  4. _write_review_file(proposal_data, req_data, name) → saves review .txt

_patch_existing(correction):
  1. generator.patch_proposal(current_data, correction, api_key) → updated dict
  2. Deletes old PPTX file
  3. builder.build_pptx(updated_data, new_path) → saves new PPTX

Output locations:
  PPTX files → C:\Users\PC\Downloads\Proposals_2026\completed\Zawad_<title>.pptx
  Review txt  → C:\Users\PC\Downloads\Proposals_2026\review_needed\Review_<title>.txt
  Log file    → C:\Users\PC\Desktop\ZawadProposalAgent\chatbot.log

GENERATOR.PY — GEMINI API CALLS
================================================================

Models tried in order (with fallback on rate limit):
  ['gemini-3.8-flash', 'gemini-3.5-flash-lite', 'gemini-1.5-flash']

MAX_RETRIES = 3
RETRY_WAITS = [30, 60, 90] seconds between retries

generate_proposal(draft_text, api_key, checklist=None):
  - max_output_tokens = 16000
  - temperature = 0.4
  - Injects RAG context (past proposals) and checklist into prompt
  - Returns complete proposal dict after fixing pricing math

patch_proposal(current_data, correction, api_key):
  - max_output_tokens = 16000
  - temperature = 0.2
  - Sends current full JSON + correction instruction → updated JSON

_extract_json(text) — ROBUST JSON EXTRACTION:
  1. Direct json.loads() attempt
  2. Strip ```json ... ``` markdown fences (greedy regex)
  3. Brace-matching to find outermost { } block
  Handles Gemini sometimes wrapping responses in markdown code fences.

_fix_pricing(proposal):
  Python always recalculates pricing (never trusts Gemini for math):
  - item.total_omr = quantity × rate_omr
  - subtotal_omr = sum of all item totals
  - vat_omr = subtotal × 0.05
  - grand_total_omr = subtotal + vat

CRITICAL FIXES APPLIED (DO NOT REVERT):

1. _tf_clear() — clears text frame and fixes OOXML bodyPr:
   def _tf_clear(tf):
       for _ in range(len(tf.paragraphs) - 1):
           p = tf.paragraphs[-1]._p
           p.getparent().remove(p)
       tf.paragraphs[0].clear()
       bodyPr = tf._txBody.bodyPr
       for tag in (qn('a:spAutoFit'), qn('a:normAutofit'), qn('a:lstAutofit')):
           el = bodyPr.find(tag)
           if el is not None:
               bodyPr.remove(el)
       if bodyPr.find(qn('a:noAutofit')) is None:
           etree.SubElement(bodyPr, qn('a:noAutofit'))
   WHY: Having both <a:normAutofit> AND <a:noAutofit> in same bodyPr is an
   OOXML schema violation that causes PowerPoint to show "problem with content"
   repair dialog every time the file is opened. After repair, some slides go blank.

2. Post-processing sweep in build_pptx() before prs.save():
   ns_a = 'http://schemas.openxmlformats.org/drawingml/2006/main'
   for slide in prs.slides:
       for el in slide._element.iter('{%s}bodyPr' % ns_a):
           norm = el.find('{%s}normAutofit' % ns_a)
           no   = el.find('{%s}noAutofit'   % ns_a)
           if norm is not None and no is not None:
               el.remove(norm)
   prs.save(output_path)
   WHY: Safety net to catch any remaining normAutofit+noAutofit conflicts.

3. _AR regex — use \u escapes NOT literal Arabic chars:
   _AR = '[\u0600-\u06ff\u0750-\u077f\ufb50-\ufdff\ufe70-\ufeff]'
   WHY: Literal Arabic characters in regex can cause encoding issues.

4. _fix_spacing() — inserts space between digits and Arabic text:
   text = re.sub('([0-9])(' + _AR + ')', r'\1 \2', text)
   text = re.sub('(' + _AR + ')([0-9])', r'\1 \2', text)
   (also handles brackets ()[])

5. Alignment rules:
   - Cover slide (title, category): PP_ALIGN.CENTER
   - Thank You / Closing slide: PP_ALIGN.CENTER
   - TOC title: PP_ALIGN.RIGHT (NOT center)
   - All other slides: PP_ALIGN.RIGHT (RTL Arabic standard)

6. Commitments slide fallback defaults when AI returns <3 items:
   defaults = [6 default Arabic commitment strings]
   if len(lines) < 3:
       lines = lines + defaults[len(lines):]

REVIEWER.PY — DUAL ADVERSARIAL REVIEW
================================================================

review_proposal(proposal_data, draft_text, api_key, requirements):
  Two-pass review:
  Pass A (Attacker): pretends to be client's rejection committee,
                     finds every weakness, gap, compliance miss
  Pass B (Defender): reads attacks, filters false alarms,
                     produces final actionable report

  Returns: full Arabic review report string with sections:
  ## ملخص تنفيذي (score / 10, ready or not)
  ## ✅ ما هو ناجح
  ## ⚠️ يحتاج تحسين
  ## ❌ مشاكل حرجة
  ## 📋 تغطية المتطلبات
  ## 🎯 أولويات الإصلاح

extract_critical_issues(review_report) → list of up to 3 critical issues

NOTE: reviewer.py is NOT called in the chatbot flow currently.
      chatbot.py has its own inline review (_write_review_file function)
      that does Python-only scoring (no extra Gemini calls).

KNOWN ISSUES AND BUGS (as of 2026-10-28)
================================================================

FIXED:
  ✅ "Problem with content" repair dialog on PPTX open
     — Caused by normAutofit+noAutofit conflict in bodyPr XML
     — Fixed in _tf_clear() + post-processing sweep

  ✅ JSON parsing failure when Gemini wraps response in ```json fences
     — Fixed in _extract_json() with greedy fence stripping + brace matching

  ✅ Token limit too small (patch was 4096 → truncated JSON)
     — Fixed: max_output_tokens=16000 for both generate and patch

  ✅ run_chatbot.bat syntax error "... was unexpected at this time"
     — Fixed: removed invalid for/f loop, uses simple taskkill

  ✅ 40-character minimum on chat input rejected file-only workflows
     — Fixed: now only blocks completely empty messages

POTENTIAL REMAINING ISSUES:
  ⚠️ If Gemini returns incomplete JSON (cuts off mid-response), the brace
     matcher in _extract_json will fail → "Cannot parse JSON" error
     → Need to retry with lower token output or split the prompt

  ⚠️ The /api/upload endpoint calls _generate_new() which returns a Flask
     Response, but the upload handler calls result.get_json() on it.
     If the server is restarted mid-upload, this can fail silently.

  ⚠️ Arabic/English spacing: _fix_spacing() runs on every text run via _para().
     Some edge cases with mixed RTL/LTR text may still show characters joined.

  ⚠️ After uploading a file, the chatbot also sends a chat message
     "تم رفع الملفات. يرجى المتابعة." — this can trigger a second
     _generate_new() call if mode is still 'await_draft'. The upload already
     called _generate_new(), so the chat call will generate ANOTHER proposal.
     → TODO: after a successful file upload sets mode='ready', the subsequent
       chat message should be handled as a patch, not a new generation.
